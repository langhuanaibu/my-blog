# 起因只抽取不推断，且由确定性闸门把关

日报每条新闻原本读不出「为什么会发生」。`context` 字段本来就在为每个精选事件生成，但只有可信延续的条目才发布——其余一律丢弃，因为 ADR 0002 要求公开 `context` 必须是已验证来龙，enrich 的泛背景不得充当回退。

决定把 `context` 改成**一个位置、两种来源**：可信延续放轨迹生成的[[来龙]]，新事件放 enrich 抽取的[[起因]]。ADR 0002 真正要守的那条不变——可信延续的轨迹生成失败时，绝不回退到 enrich 文本。

关键约束是**只抽取、不推断**。事件因果抽取的研究结论很一致：推断未陈述的因果不可靠（真实文本上最强模型 F1 约 0.48，专做该任务的零样本框架在学术基准上也只有 42–53%），主导失败模式是把语义关联当成因果——正是本仓库客观性红线禁止的那一类。可靠的只有抽取原文已明说的因果。

因此把出处验证与语义成立拆成两层责任，而不是靠提示词自觉：

1. **多片段出处核对**：模型写起因时可交出最多三条 `{source_index, quote}`。管线逐条校验来源索引、长度，并在对应来源正文中做归一化后的精确匹配；任一片段非法就丢弃整段起因。改写过的引文一律视为不合格。
2. **全文语义审计**：片段存在只证明引文确实来自该来源，不证明起因里的每个因果判断都能由引文推出。全文模式的独立客观性审计必须检查完整 `context`，任何证据外因果关系都判为不通过。

未归因推测拦截仍作为确定性补充：起因里出现推测或动机语气而不归属给任何一方的，直接丢弃。

## Considered Options

- **只改提示词口径**：实测无效。连跑两轮，明令禁止的「复述当日事实」和「写成走向」原样复现，客观性审计也未拦住。
- **新增独立 `cause` 字段**：语义更清晰，且延续事件能同时有来龙和起因；但 ADR 0001 已否决过新增第五段，且要动字段表、审计、前端多处。当前多数事件没有来龙，语义重叠的顾虑不成立，故复用。
- **只靠第二次 LLM 判断做精度闸**：审计不能替代可回放的出处校验；但出处校验也不能判断因果蕴含。因此采用确定性出处核对加独立语义审计，而不是二选一。

## Consequences

- 覆盖率显著低于旧行为：放开发布约 53%，加片段核对后降到约三分之一。**这是刻意的取舍，不得为提高覆盖率放宽核对。**
- 起因质量取决于素材：`objectivity.mode` 为 `interim` 时 enrich 只看到 200 字 RSS 摘要并沿用短内容合同；shadow／active 才使用全文深度合同和完整语义审计。
- 轨迹回滚开关关闭时起因一并消失——它占的是来龙的位置，同受该闸门管辖。
- 起因不投影进轨迹 review cases：Judge 只审连续性与历史支撑，对起因没有判据，放进去会让新事件因无关字段拖垮轨迹门。
- 残留风险：把来源事实（如嫌犯背景）放进「为何发生」的位置仍可能暗示动机。语义审计也不是确定性证明，仍需人工抽样复核。
