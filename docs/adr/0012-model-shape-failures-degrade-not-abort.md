# 模型返回形状非法时管线降级，不中止

2026-08-01 的定时日报没有发出去。Run 30674149780 抓完 320 条、写完全量轻档，崩在阶段A 最后一批（2 条）：

```
File "news-pipeline/daily_news.py", line 2040, in triage
    ids = [i for i in ev.get("ids", [])
AttributeError: 'str' object has no attribute 'get'
```

`TRIAGE_SYSTEM` 要求「只输出 JSON 数组」，模型这一批退化成只返回一个对象。`triage()` 直接 `for ev in result` 再 `ev.get(...)`，迭代 dict 拿到的是字符串 key，一批脏返回把整条管线炸掉，崩在 commit 之前，当天线上没有日报。

真正的问题不是这一个 `.get`。代码库在「模型返回形状非法怎么办」上本来就三种写法并存：`prefilter` 包 `try/except` 丢整批，阶段B（`enrich`）逐元素 `isinstance` 过滤，归并与审计走 `_validated_*` 包装，而 `triage` 两样都没有。**故障是这个不一致的必然结果**，不是偶发。

再往下挖一层，不一致的源头是**两种输出契约并存**。归并与审计要的是对象包裹（`{"groups": [...]}`），形状不对就干净拒绝；而阶段A、阶段B、深读、论文、舆论观察要的是**裸数组**。模型在答案只有单个元素时极易丢掉数组外壳、直接返回裸对象——这正是 08-01 的形状。裸数组契约让「一个元素」和「整个结果」在 JSON 里无法区分，对象包裹让它们永远可区分。

诱因是批次大小：崩掉那批只有 2 条，而历史十次尾批都在 13 条以上。输入越少，答案越可能只有单个元素，丢外壳的概率越高。

决定一：**对象包裹是本仓库模型输出的默认契约。** 提示词一律要求 `{"<key>": [...]}` 并显式写明「只有一个也必须放进数组」，新增调用点不得再用裸数组。归一化统一走 `_model_rows(raw, key)`：主契约优先，裸数组作兼容回退（模型偶尔回到旧格式不算故障），单个对象按单元素处理，其余判为整体不可用。

`_model_rows` 里判定「键名漂移」用的是**整个对象只有一个键**，不是「唯一的列表值」。后者会误判：丢了外壳的裸行对象自己就带 `ids` / `claims` / `context_evidence` 这类列表字段，按「唯一列表」会把 `ids` 当成行列表——恰好在本次故障那个形状上判错。包裹对象只有一个键，行对象总是带一堆字段，按字段数区分不可能误判。

决定二：**任何 `json_call` 调用点都必须假定返回形状不可信；形状非法时管线降级，不中止整跑。**

降级方向必须是**不丢内容**：能归一化就归一化（单个对象包成单元素数组），不能归一化就退到最保守的可用形态。具体到 `triage`，整批不可用时该批每条降级为单条独立事件（`category` 取 `world`、五维取默认 3.0、标题取来源原标题），而不是跳过该批——阶段A 是聚类步骤，跳过一批等于这些条目彻底不进事件层，日报照常发布，表面看不出来少了。代价是该批不去重，由末尾的全量同日归并接住。

「模型没挑出东西」和「模型跑偏了」必须分开：空数组是合法回答（该批全是垃圾），非空但一个可用行都没有则按整批不可用处理。两者混同会让后者静默丢光整批条目。

判「跑偏」不能只看元素是不是对象，还要看**有没有真的落地事件**。行全是合法对象、但编号全落在本批窗口外（模型用了批内相对编号，这是 `triage` 里早有注释的已知行为），或者退化成一个空对象 `{}`，都会让这批条目一个不剩地消失，而形状检查完全看不出来。因此 `triage` 在「有行但产出为零」时同样降级为单条事件。

降级必须记账，不得静默：非法元素记 `triage_invalid_rows`，整批降级记 `triage_fallback_batches`，任何调用点上的「整体不可用」记 `model_unusable_responses`，同时置 `quality["degraded"]` 并打日志，随 `quality-health.json` 落盘。深读、论文、舆论观察是独立故障域、手上没有 `quality`，至少要打一行日志——它们此前是**连日志都没有**的静默变空。

决定三：**分批不得产生极小的尾批。** `batch_spans` 在尾批不足 10 条时并入前一批。阈值 10 由实测标定：历史十次尾批是 13/14/17/18/20/27/28/35/36/43，出事那次是 2，阈值落在 2 和 13 之间的空档，常规日子的分批边界完全不变。

## Considered Options

- **保持 fail-closed，只是报错更清楚**：宁可不发也不发残品。但阶段A 一批脏返回并不意味着当天新闻不可用——本次故障里前 6 批共 300 条全部正常，为最后 2 条放弃整天日报，代价与收益不成比例。日报是每天一次的通读产物，缺一天补不回来。
- **照抄 `prefilter` 的「批次失败就丢整批」**：实现最省事，但两者降级方向相反。`prefilter` 丢批的语义是「该批全部保留」，宽松无损；`triage` 丢批的语义是「该批全部丢弃」。同样一行 `except: continue`，在这里是内容损失。
- **在 `json_call` 层统一做 schema 校验**：看起来更彻底，但十几个调用点的期望形状各不相同（数组/对象/分组数组），统一层只能校验到「是不是 JSON」这种无用粒度，真正的形状约束仍然落在各调用点。而且改动面覆盖全部调用点，与本次故障的作用域不成比例。
- **让降级当天判 `needs_review` 卡住验收门**：信号最强，但要改 `rollout_validation.py` 和评判口径。降级是诊断信号不是质量结论——一批 50 条里少一次聚类，不足以否定当天的选品结果。
- **只做防御性归一化，不动提示词契约**：零回归风险，也能接住已观测到的形状。但它治的是症状：裸数组契约本身让「一个元素」和「整个结果」不可区分，下一个变体照样中招。既然要改，就把歧义从源头去掉。
- **开 provider 的 `response_format: json_object`**：让供应商保证输出是 JSON 对象。基础设施已经支持（`extra_body` 直通，指纹里也已追踪 `response_format`），但它倾向强制顶层对象，与十几处解析口径的关系需要单独验证；本决策的对象包裹契约已经覆盖同一风险面，且不引入供应商差异。留作后续独立决策。
- **均匀分批（302 条分成 7×43）**：彻底没有小批，但每天的分批边界都会变，聚类结果整体偏移。尾批阈值只在离群值出现时改变行为，验收期内扰动小得多。

## Consequences

- 阶段A 不再能因为单批脏返回中止整跑。极端情况下（全部批次都降级）当天日报变成完全不去重的条目流，质量明显下降但仍然产出，且 `quality-health.json` 里留有全部证据。
- 降级批次会引入重复事件，压力转移到 `reconcile_same_day_events`。它本来就是全量同日归并，且自带确定性降级路径。
- `triage_invalid_rows` / `triage_fallback_batches` / `model_unusable_responses` 只做诊断，**不参与任何判定或验收门**。不得在 `rollout_validation.py` 里给它们加判定而不重开本决策。
- 提示词与分批逻辑都在 `daily_news.py` 里，而 `runtime` 指纹哈希的是整个文件字节，因此本决策落地会重置 Selection / Trajectory 时钟。落地窗口选在 2026-08-01——当天已因发布失败归零，沉没成本为零。
- 本轮改了五个裸数组调用点：`triage`、`enrich`、`deep_channel`、`papers_channel`、`opinion_pulse`。**新增调用点必须用对象包裹 + `_model_rows`。**
- `MERGE_SYSTEM` / `merge_events` 仍是裸数组，但生产已无调用者（只有测试在用），因此未纳入本轮改造。若将来重新启用，必须先切到对象包裹。`VOCAB_*` 属停用功能，同理。
- 本决策不追认「日报可以发残品」。它划的边界是：单个模型调用的形状抽风属于可降级故障；数据校验（精选非空、文件完整）失败仍然中止不提交，那条边界不变。
