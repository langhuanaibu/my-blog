# 后台发布的文章使用显式永久链接

Hexo 的全局时区设为 `Asia/Shanghai`，而 Vercel 构建进程可能运行在 UTC。只给 `date` 写入纯日期或午夜时间时，Hexo 会在解析后再次应用站点时区，导致同一篇文章在不同构建环境中落到不同的 URL 日期。把时间统一改成中午可以绕开大部分情况，但显式的早间发布时间仍会偏移，而且 `date` 作为发布元数据不应同时承担链接稳定性。

后台新建文章时，根据用户选择的日历日期和已经解决文件名冲突后的 slug 写入 `/YYYY/MM/DD/slug/` 形式的 `permalink`。主动修改文章日期时，只更新永久链接的日期段，沿用已有永久链接或文件名中的稳定 slug；只改标题或时间时保留链接。旧文章日期未变化时原样保留：已有显式永久链接的继续使用，没有的也不会在普通编辑中被迁移。

## Considered Options

- **把纯日期改成当天中午**。能避开当前 UTC 与上海时区组合下的午夜回退，但无法覆盖显式早间时间，规则也难以从 Front Matter 本身解释。
- **修改 Hexo 全局时区**。会重新解释全部历史文章，影响范围包含既有 URL 和评论路径，不符合增量兼容要求。
- **继续让 URL 完全由 `date` 推导**。构建环境变化仍可能改变路径，无法提供永久链接保证。

## Consequences

- 后台发布文章的 `date` 只描述发布时间；URL 由显式 `permalink` 固定，在 UTC 和上海时区构建中应保持一致。
- 新文章最终 slug 来自实际文件名，因此文件名冲突产生的 `-2` 等后缀也会进入永久链接，不会出现文件与链接重名。
- 历史文章不批量补链接。为避免迁移评论路径，只有新文章、已经带链接的文章和用户主动改期的文章进入新策略。
- 手工修改显式永久链接属于 URL 迁移，必须同时考虑重定向与评论关联，不能把它当作普通标题编辑。
