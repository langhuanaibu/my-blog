# 次级条目不写摘要，非中文来源原文留空

[[次级]]条目不进入精选深加工，因此它们的摘要位从来不是日报写的——`event_to_item` 一直把来源原文摘要（RSS `desc`）截前 100 字直接放进去。中文源没问题，英文源就把一句没翻译的外语原句摆在了摘要位上。全历史 231 条次级摘要里 **154 条（67%）是纯英文原句**，读起来像是日报自己写的中文摘要，实际不是。

`CONTEXT.md` 对[[次级]]的定义本就是「只列在更多资讯里的条目」，日报不为它撰写内容。所以这不是「翻译漏了」，是**回退素材不该无条件采信**。

决定：**回退只在来源原文本身可直接阅读时才采用，否则摘要位留空。** 判定按中文字符占比，阈值 0.15。阈值由实测标定——中文条目最低占比 0.22，英文条目全为 0.00，0.1~0.2 之间没有任何样本，阈值落在这个空档正中，两侧都有充足余量。

序列化（`event_to_item`）与审计投影（`_materialize_reader_projection`）共用同一判定。后者的契约就是「暴露与 `event_to_item` 完全一致的默认值」，两边各改一处，客观性审计就会去审一段永远不会发布的文字。

## Considered Options

- **翻译次级摘要**：要么在阶段 A 的输出里加字段，要么单独加一次调用。阶段 A 面向全部候选事件（数百条）而不只是最终那 8 条次级，输出 token 涨幅与收益不成比例；更根本的是，这等于把次级升级成「日报为它撰写内容」，与它的定义冲突。
- **保持照登英文原文**：零成本，但把来源原句冒充成日报摘要，与客观性上「不把别人的表述写成自己的」同一类问题。读者也明确反馈这读起来不对。
- **只在前端隐藏非中文摘要**：数据里仍然带着这段文本，RSS、搜索索引、事件线历史任何一处将来接上它都会重新泄漏。要治就在产出端治。

## Consequences

- 约三分之二的次级条目此后只有[[展示标题]]和来源链接，摘要位为空。**这是刻意的取舍**，符合[[次级]]的定义，不得为了「看起来充实」把英文原文放回去。
- 次级详情页相应变薄（标题 + 元信息 + 相关链接 + 操作区）。它的价值本就是出站读原文，不是站内阅读。
- 事件线历史里，次级条目早有 `summary or title` 回退，会自动改记中文标题；精选那条同步补齐了同样的回退，避免 enrich 失败时写入空字符串。
- **历史数据不回填**。已发布的日报文件里那 154 条英文摘要保留原样，`events.json` 的事件线历史同样保留。回填要两边一起改，属于重写已发布数据，需单独决策。
- 若将来 `objectivity.mode` 切到 `active`，次级仍然不跑深加工，本决策不受影响。
